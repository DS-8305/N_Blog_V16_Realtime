# 실시간 이슈 조사·작성 지침

입력은 사용자의 주제와 현재 작업의 `request.json`이다. Codex가 실제 웹 조사를 수행하고 `research.json`, `post.json`을 작성한다. CLI가 스스로 원고를 생성한다고 안내하지 않는다.

## 조사

- 실제 서울 기준 조사시각을 기록한다. 최근 72시간의 동향을 먼저 찾고 오래된 배경은 사건 날짜를 분리한다.
- 공식 기관·당사자 발표와 관련 원문을 직접 읽고 가능한 경우 별도 보도로 확인한다. 제목이나 검색 요약만으로 수치·인용을 확정하지 않는다.
- 출처의 `publishedAt`, `updatedAt`은 확인한 값만 사용하고 미표시는 `null`이다. `accessedAt`과 캡처일을 게시일로 바꾸지 않는다.
- 사실마다 `factId`와 근거 `sourceIds`를 연결한다. 의혹·추측을 확정 사실로 바꾸지 않는다.

현재 사실은 `temporalRole: "current"`(생략 시 기본값), 과거 배경은 `"background"`로 구분한다. 현재 사실마다 최근 72시간 이내 게시·수정일을 확인한 근거를 연결하고 본문에서 현재 사실을 하나 이상 사용한다. 조사 묶음도 72시간 이내여야 한다. 접속시각을 게시일로 대신하거나 무관한 최신 기사로 최신성을 채우지 않는다.

## 연예 홈판용 작성 규칙

- **제목**:
  - 글자 수 35~45자 (최대 50자).
  - 숫자 1개 이상 필수 포함.
  - **단일 패턴 반복 금지**: 구글 시트 '제목템플릿' 탭(`config/title-templates.json`)의 17가지 틀을 이슈 성격(근황, 반전, 미끼+정체, 숫자 대비, 자문형, 패션, 외모 변화 등)에 맞춰 고루 순환 적용할 것:
    1. **따옴표 훅**: `"[대사·속마음·반응]"` + `[인물/숫자]` + `[상황]` + `[결과/대상]` (예: “한 달에 1천만원 쓴다” 81세 임현식..손절한 주식은 10배 폭등, 재산 정리 고민까지)
    2. **따옴표 훅(의문)**: `“[감탄·의문 대사]?”` `[이름]` `[이름]`, 갑자기 전해진 소식 (예: “결혼하고 9개월 만에 이게 웬일?” 김우빈 신민아, 갑자기 전해진 소식)
    3. **twodays 근황**: `'[나이]'` `[이름]`, `[형용]` 근황... 결국 조용히 전해진 소식 (예: '55세' 유해진, 심상치 않은 근황... 결국 조용히 전해진 소식)
    4. **twodays 오해**: `[이름]♥[이름]`, `"[관계 표현]"`.. 뒤늦게 발칵 (예: 송혜교♥강동원, "운명처럼 빠진 관계".. 뒤늦게 발칵)
    5. **twodays 반전**: `'[A]하자마자 [B] 소식?'` `[이름]♥[이름]`, `[대상]`은 따로 있다 (예: '결혼 발표하자마자 결별 소식?' 솔비♥이규한, 상대는 따로 있다)
    6. **미끼+정체**: `[유명인 A·B]`도 있었는데..`[반전]` 여배우의 정체 (예: 이민정·이영애도 있었는데..그날 유독 사진 퍼진 여배우의 정체)
    7. **미끼+정체2**: `[유명인]`랑 `[공통점]`.. `[숫자]`년 전 이미 `[사건]`까지 한 연예인의 정체 (예: 이효리랑 맞춰 입은 커플옷.. 4년 전 이미 혼인신고까지 해둔 연예인의 정체)
    8. **숫자 대비**: `[숫자 A]`인데 `[대비 숫자 B]` + 드라마/영화 (예: "300억 대작인데 고작 4%.." 3일만에 1위 찍고 해외까지 터진 드라마)
    9. **자문형**: `[지표 낮음]`인데 `[질문]`?..`[다른 지표]` 1위 + 드라마 (예: 시청률 1~2%인데 망작인가?..화제성은 4주 1위, 넷플릭스 9위 쓴 드라마)
    10. **반전 말줄임**: `[숫자 기간+사건]`.. 또 `[반전]`한 연예인 (예: 이혼 8년 만에 미국에서 9살 연상과 극비리 결혼식 올렸는데.. 또 이혼한 연예인)
    11. **패션 비교**: `[나이]` `[유명인]`이 입었을 땐 몰랐는데.. `[나이]` 여배우가 같은 `[옷]` 입자 달라진 이유 (예: 30대 김고은이 입었을 땐 몰랐는데.. 50대 여배우가 같은 드레스 입자 분위기 달라진 이유)
    12. **패션 vs**: `[장소 A]`에선 `[좋음]`... `[장소 B]`에선 `[반응 갈림]` `[A]` vs `[B]` 패션 (예: 부산에선 리즈더니... 런던에선 호불호 갈린 전도연 vs 조여정 패션)
    13. **패션 숨김**: `[유명인]`은 없었다.. `[브랜드]`가 `[선택]`한 `[나이대]` 연예인 패션 (예: 제니, 고윤정은 없었다.. 샤넬이 단독으로 모셔간 10대 연예인 패션)
    14. **외모 변화**: `[숫자 사건]`.. `[행동]` `[나이]` `[이름]` (예: 안면거상 2번 뒤 또 병원.. 티타늄 리프팅 받은 68세 심형래)
    15. **반가운 소식**: `[나이]` `[이름]`, 갑자기 들려온 반가운 소식♥.. “`[축하]`” (예: 43살 배정남, 갑자기 들려온 반가운 소식♥.. “축하합니다”)
    16. **리빙(예능)**: `“[감상 대사]”` `[예능]` 속 `[집]`에서 눈에 띄는 `[공통점 N가지]` (예: “부부보다 집에 먼저 눈이 갔어요” 이혼숙려캠프 속 집에서 눈에 띄는 공통점 3가지)
    17. **지칭어 숨김**: `"[반응 대사]"` `[대상]`이 `[염원]`했다는 '이 드라마' (예: "진심 너무 닮아서 얼굴합 ㄹㅈㄷ..." 전국민이 둘의 연애를 염원했다는 '이 드라마')
  - `titleCandidates` 7개는 반드시 위 17가지 템플릿 중 서로 다른 7개의 틀을 각각 적용하여 다채롭게 구성할 것. 작성된 7개의 제목 후보는 본문 해시태그 뒤에 `[제목 후보]` 7개 목록으로 자동 추가되어 사용자가 네이버 블로그 에디터에서 최종 제목을 직접 교체 선택할 수 있음.
  - `titleTemplateIds`에 각 후보와 같은 순서의 유효 ID 7개를 기록하고 중복하지 않는다. 예시는 구조 참고용이며 실제 후보는 숫자·길이·기호 조건을 모두 충족해야 한다. 46~50자는 권장 길이 경고, 35자 미만·50자 초과는 거부한다.
  - 줄임표 `…`(한 글자 유니코드) 및 느낌표 `!` 사용 금지 (`..` 또는 `...` 사용).
  - 물음표 `?`는 따옴표 안 또는 자문형/틀에서 허용된 형태 외 남발 금지.
  - 최종 제목은 `research.json`에 수집한 각 기사 제목과 겹침이 60% 미만이어야 함. 공백·문장부호를 제거한 글자 bigram 집합의 Jaccard 유사도를 기준으로 하고, 기사 제목 bigram 대비 공통 bigram 비율도 함께 보고. 60% 이상이면 기사에 없는 줄거리·캐릭터·장면 키워드로 바꿔 다시 쓸 것.
- **첫 문단**:
  - 도입부 첫 문단에서 제목이 던진 궁금증에 지체 없이 바로 답변.
- **문체**:
  - 원고 전체를 `~했어요 / ~이에요` 친근한 구어체로 통일.
  - `~했습니다 / ~입니다` 격식체 금지.
- **소제목**:
  - 네이버 에디터 인용구 서식 4~6개.
  - 첫 번째 소제목은 제목의 핵심 키워드/훅을 다시 활용해 작성.
- **분량 및 이미지**:
  - 본문 공백 포함 1,000~1,600자.
  - 소제목 4~6개에 걸쳐 이미지 총 10~12장 (소제목별 2~3장씩 세로 배치).
  - 사진별 캡션(caption)은 쓰지 않음 (비우거나 생략, 값이 있으면 `image_caption_forbidden`).
  - `post.json`의 `photoSources`에 실제 사용한 사진의 진짜 출처(매체·공식처)만 중복 없이 적음 (예: `["연합뉴스", "뉴시스"]`). 언론·공식 페이지 사진을 우선.
  - 본문 맨 끝, 태그 바로 위에 `사진 출처 : 매체A, 매체B` 한 줄만 자동 삽입되며, 기존의 전체 자료 출처 목록은 본문에 붙이지 않음.
- **끝맺음**:
  - `한 줄 정리: ...` 1줄 작성.
  - 이어서 독자에게 묻는 질문 1줄 작성 (예: `여러분은 이번 소식 어떻게 생각하시나요?`).
  - 그 바로 아래에 인용구 소제목 `함께 보기 좋은 이슈`를 배치. `post.json`의 `conclusion` 배열에는 `["한 줄 정리: ...", "독자 질문...", "함께 보기 좋은 이슈"]` 형태로 분리해 적고 접두사 없이 소제목 명칭만 작성할 것. 관련 글 3개는 `config/related-posts.json`의 URL을 정해진 순서로 준비 단계에서 자동 삽입하므로 `post.json`에 카드 자리 표시나 링크를 직접 쓰지 말 것. 사용자가 변경을 지시하기 전까지 이 설정을 유지.
- **태그**:
  - 관련 핵심 키워드로 태그 10개 작성.

## 원고

- 제목 후보 7개, 같은 순서의 서로 다른 템플릿 ID 7개와 선정 제목 1개를 만든다. 핵심 검색어와 확인된 변화·이유를 자연스럽게 담는다.
- 도입부 → 소제목 4~6개 → 마무리로 쓴다. 소제목마다 짧은 본문을 넣고 공백 포함 총 1,000~1,600자로 맞춘다.
- 글자 수는 도입부·소제목·문단·마무리를 `\n\n`으로 이어 붙인 길이다. 제목·사진 출처·태그는 제외한다. `post:check` 출력으로 확인한다.
- 짧고 자연스러운 한국어로 작성하고 번역투·상투어·작성 과정 설명을 빼라. 확인되지 않은 사실·수치·인용을 채워 넣지 않는다.
- 각 섹션의 `factIds`에 해당 본문이 사용하는 근거를 연결한다. 태그는 관련성 있는 10개로 작성한다.

## 이미지

- 각 섹션의 `images` 배열은 기본 2~3개, 전체 10~12개다. 사용자 명시 재정의가 없으면 최대 12장을 넘기지 않는다.
- `slotId`는 글 전체에서 유일한 영문·숫자·하이픈 조합이다. 사진별 설명(caption)은 작성하지 않는다.
- 다운로드: `mode: download`, 서로 다른 장면을 찾는 `query`를 쓰며, 구글 검색(`engine: google`, CDP 9230)을 우선한다. 필요한 이미지를 확보하기 어려운 경우 네이버 검색(`engine: naver`)이나 확인한 원문 이미지·캡처로 보완한다. 구글 인증·트래픽 제한은 우회하지 않고 `AGENTS.md`의 대응 지침을 따른다.
- 검색어를 인물·사건·장면·출처 요소로 나눠 각각 검색하고, 이후 2~3개 요소를 조합해 검색·수집·사진 검토를 반복한다. 원하는 장면이 없거나 중복·긴 합성 사진·무관한 추천 이미지가 많으면 검색 요소를 바꿔 보완한다.
- `image:search`는 검색어당 후보 5장·35초로 시작한다. `image:candidates`의 실제 사진과 원출처를 보고 중복을 제거한 뒤 `image:select`로 슬롯에 배정한다. `image:collect`도 최대 3개 미확보 검색어의 후보만 모으며 첫 사진을 자동 선택하지 않는다. 충분한 사진을 골랐으면 검색을 멈추고, 부족한 장면만 새 검색 요소/조합으로 보완한다.
- 일반인 개인 블로그·인스타그램 원사진은 금지한다. 언론 재게재도 원출처가 개인/미확인이면 제외한다. 원출처를 `publisher` 또는 `official`로 실제 확인한 경우에만 선정하며, 차단된 플랫폼의 공식 계정은 `config/image-source-policy.json`에 근거와 정확한 계정·사진 URL을 검증 등록해야 한다. 출처를 추정해서 채우거나 개인 계정을 공식으로 표기해 통과시키지 않는다.
- 이미 수집한 후보는 재다운로드하지 않고 검토·출처가 연결된 캐시 파일에서 가져온다. 사진의 다른 크기·압축본은 같은 장면인지 확인하고, 다른 출처에서 발견된 동일 사진은 확인 가능한 출처를 선택한다. 유사 사진을 별도 장면으로 쓰려면 직접 확인한 근거와 `--distinct-scene true`를 기록한다.
- 직접 확인한 원본 URL은 `engine: direct`, `sourceId`, `imageUrl`, `originKind: publisher|official`, `originUrl`로 지정할 수 있다. `query`에는 실제 검색어나 장면 설명을 기록한다. 확인되지 않은 원출처로 새 다운로드를 진행하지 않는다.
- 캡처: `mode: capture`, 실제 확인한 `sourceId`, `url`, `selector`, `requiredLabels`, `originKind`, `originUrl`을 쓴다. 필요하면 `frameSelector`를 지정한다.
- 인물 모습·현장·발표 자료처럼 소제목에 필요한 서로 다른 장면을 고른다. 같은 사진의 크기만 바꾸거나 무관한 사진으로 수량을 채우지 않는다.
- 원본 비율을 보존한다.
- 모든 이미지를 실제로 보고 본문과의 관련성·인물·날짜·중복·잘림을 확인한 후 최종 검토 기록을 남긴다.

사진 출처는 `post.json`의 `photoSources`에만 작성한다. 본문 문단에 다시 넣어 중복하지 않는다. 섹션의 `paragraphs`는 이미지마다 한 문장씩 같은 순서로 작성한다. 개수는 `images`와 정확히 같아야 한다. CLI는 인용구 → 이미지 1 → paragraphs[0] → 이미지 2 → paragraphs[1] → 이미지 3 → paragraphs[2] 순서로 교차 입력한다. 각 항목은 일반 본문이며 모바일 줄바꿈을 유지한다.

## 모바일 가독성 줄바꿈 규칙

모바일 글꼴 16 기준으로 한 줄이 25자를 넘으면 어색하게 줄이 넘어간다. 사용자가 직접 손본 이세돌 글(https://blog.naver.com/my_income/224450439506)을 기준으로 삼는다.

1. 본문 한 줄은 15~20자, 최대 20자. 숫자를 맞추려고 의미를 억지로 끊지 말고, 20자 안에서 의미가 끊기는 곳을 골라 줄을 바꿀 것.
2. 줄바꿈 위치: 쉼표 뒤, '~며/~고/~는데' 같은 연결어미 뒤, 긴 주어나 수식어 덩어리가 끝나는 곳. 서술어로 끝나는 마지막 부분은 따로 한 줄로 둘 것.
3. 한 문장은 여러 줄로 나누고, 한두 문장(3~4줄)마다 빈 줄 하나를 넣을 것.
4. 소제목과 사진 설명 앞뒤에는 빈 줄을 넣지 말 것. '한 줄 정리'는 레이블을 그대로 두고 한 줄로 쓰며 앞뒤에 빈 줄을 넣을 것. 마지막 질문도 같은 기준으로 나눌 것.
5. 문장 끝(. ? ! .. 또는 ~요/~다)이 아닌 12자 미만 줄은 `post:check`가 `short_line` 경고(줄 번호·글자 수)를 낸다. 저장은 막지 않지만, 다음 줄과 합쳐 15~20자로 맞출 것.
